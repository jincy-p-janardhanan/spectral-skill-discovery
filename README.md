# Spectral Skill Discovery (SSD)

Implementation of the SSD algorithm (Spectral Skill Discovery): a METRA-style skill learner whose encoder
dimensions are **ordered** by asymmetric decorrelation constraints, trained with an augmented
Lagrangian (duals β, ν and a growing barrier c). A permutation-tested **spectrum readout** estimates
the intrinsic skill dimension K⋆.

Environments, observations, normaliser presets, network sizes and SAC details follow the official METRA
implementation ([seohongpark/METRA](https://github.com/seohongpark/METRA)), so results are directly comparable.
The code itself is new and self-contained: METRA's garage / gym / mujoco-py stack only runs on Python 3.8.

## Requirements

- Python 3.14, PyTorch 2.14 (CUDA 12.6 build), Gymnasium 1.3, MuJoCo 3.14, NumPy 2.5
- [uv](https://docs.astral.sh/uv/)
- A CPU with AVX (MuJoCo 3) and, for the pixel environments, an NVIDIA GPU with EGL for offscreen rendering.
  torch is installed from PyTorch's `cu126` index, which needs an NVIDIA driver for CUDA 12.6 or newer.

```bash
uv sync            # creates .venv with the pinned versions from uv.lock
uv run pytest      # unit tests (no MuJoCo needed)
```

## Training

`uv run train.py --help` lists every flag. The algorithm's hyperparameters all live in `SSDConfig`
([ssd/algorithm.py](ssd/algorithm.py)), and each field is exposed as a flag of the same name. The defaults of
`train.py` are not the benchmark settings; use the commands generated by `make_commands.py` (below) for those.

Outputs go to `exp/<run_group>/<env>_K<K>_s<seed>/` (with `--resume 1`, as in the generated commands):
- `progress.csv`: training scalars (J, h, mean |C|, ν, c, SAC stats).
- `eval.csv`: K⋆, σ²ₖ, Rₖ and floorₖ for every k, plus coverage (Kitchen: tasks achieved).
- `plots/`: spectrum and x-y trajectory figures at every evaluation, plus per-dimension sweeps for continuous skills.
- `tb/`: TensorBoard logs.
- `checkpoint.pt`, `checkpoints/`: latest and periodic checkpoints.
- `resume.pt`: agent, optimisers, replay buffer and RNG states. Rerunning the same command continues from it.

## Reproducing the results

### 1. SSD runs

`make_commands.py` writes one `train.py` command per line: the 5 environments with 8 seeds each, using the
per-environment settings of METRA's benchmark. One METRA epoch (8 trajectories, then
`trans_optimization_epochs` updates) is one SSD iteration.

| Env | Obs | Skills | T | Updates / iter | Buffer | Iterations | Eval every |
|---|---|---|---|---|---|---|---|
| `ant` | state (29-D) | 2-D unit-length | 200 | 50 | 1M | 10,001 | 500 |
| `half_cheetah` | state (18-D) | 16 cube (K = 4) | 200 | 50 | 1M | 10,001 | 500 |
| `dmc_quadruped` | 64x64 RGB x3, action repeat 2 | 4-D unit-length | 200 | 200 | 300k | 2,001 | 100 |
| `dmc_humanoid` | 64x64 RGB x3, action repeat 2 | 2-D unit-length | 200 | 200 | 300k | 3,201 | 160 |
| `kitchen` | 64x64 RGB x3 | 32 cube (K = 5), fixed α | 50 | 100 | 100k | 2,501 | 125 |

The pixel environments also use the per-dimension temporal bound (`--temporal_per_dim 1`), one encoder network
per dimension (`--encoder_per_dim 1`) and scale-aware decorrelation (`--decor_scale 10`).

```bash
uv run make_commands.py --run_group Benchmark --out commands/main.txt    # 40 runs
uv run make_commands.py --sweep --out commands/sweep.txt                 # 54 runs, groups exp/Tune/<env>_<setting>
```

Each line is an independent run; spread them over your GPUs or cluster jobs however you like, e.g.

```bash
source .venv/bin/activate
sed -n 1p commands/main.txt | bash      # Ant, seed 0
bash commands/main.txt                  # everything, one run after another
```

### 2. Baselines

METRA, LSD and DIAYN are run with the official METRA code, using the commands of its README with seeds 0-7.
The scripts below read those runs from METRA's experiment directory (`--metra_dir`), identifying the method, seed
and environment of each run from its `debug.log`.

### 3. Tables and figures

```bash
# Coverage / tasks achieved over training, final values with exact permutation-test p-values against SSD
# (final_coverage.csv), and the trajectories of the median seed. --baselines METRA gives the SSD vs. METRA
# trajectory figure.
uv run compare_metra.py --ssd_dir exp/Benchmark --metra_dir <metra_run_group> --baselines METRA LSD DIAYN \
    --envs ant half_cheetah --out figures/state
uv run compare_metra.py --ssd_dir exp/Benchmark --metra_dir <metra_run_group> --baselines METRA LSD DIAYN \
    --envs dmc_quadruped dmc_humanoid kitchen --out figures/pixels

# Spectrum readout across seeds (final spread and return per dimension, spread over training) and K* per seed
uv run plot_spectrum_summary.py --groups "ant=exp/Benchmark/ant_*" "half_cheetah=exp/Benchmark/half_cheetah_*" \
    --out figures/spectrum/state
uv run plot_spectrum_summary.py --groups "dmc_quadruped=exp/Benchmark/dmc_quadruped_*" \
    "dmc_humanoid=exp/Benchmark/dmc_humanoid_*" "kitchen=exp/Benchmark/kitchen_*" --out figures/spectrum/pixels

# Stability of K*: the readout rerun offline on the final encoders and replay buffers
uv run readout_sweep.py --runs "exp/Benchmark/ant_*" --min_ratio 0.05 --out figures/readout/ant.txt
uv run readout_sweep.py --runs "exp/Benchmark/half_cheetah_*" --min_ratio 0.05 --out figures/readout/half_cheetah.txt

# Hyperparameter sweep: coverage at 8M steps, against the main runs' seeds 0-2 at 8M steps as the defaults
uv run plot_ablation.py --env ant --max_steps 8e6 --groups "defaults=exp/Benchmark/ant_K2_s[012]" \
    --group_dirs "exp/Tune/ant_*" --metra_dir <metra_run_group> \
    --legend_outside --out figures/sweep/ant.png
uv run plot_ablation.py --env half_cheetah --max_steps 8e6 --groups "defaults=exp/Benchmark/half_cheetah_K4_s[012]" \
    --group_dirs "exp/Tune/half_cheetah_*" --metra_dir <metra_run_group> \
    --legend_outside --out figures/sweep/half_cheetah.png
```

The mean |C_kj| between dimensions is logged as `ssd/C_abs_mean` in `progress.csv`. The same objective without
the decorrelation constraint is trained by adding `--eta_beta 0 --c0 0` to a command.

## Code map

Where each part of the SSD algorithm is implemented:

| Part | Where |
|---|---|
| Initialisation (θ, ω, ψ, β = 0, ν₀, c₀, D) | `SpectralSkillDiscovery.__init__`, `TrajectoryBuffer` |
| Sample z, roll out T steps | `train.py` loop, `ssd/rollout.py` |
| Intrinsic reward, SAC | `SpectralSkillDiscovery.update`, `ssd/sac.py` |
| Two batches, C_kj, h, Ĵ, L, ascent on θ | `spectral.decorrelation`, `spectral.temporal_hinge`, `spectral.skill_objective`, `spectral.lagrangian` |
| Duals every n_dual updates | `SpectralSkillDiscovery.update` |
| Barrier | `SpectralSkillDiscovery.update` |
| Spectrum readout, permutation test, K⋆ | `SpectralSkillDiscovery.spectrum`, `spectral.spectrum_readout` |

## Implementation notes

- **Iterations.** One iteration collects `--rollouts_per_iter` trajectories, then runs `--updates_per_iter` updates.
  `n_dual` counts updates and `n_eval` counts iterations. Updates start once the buffer holds
  `--min_buffer_size` transitions, as in METRA.
- **Readout.** The spectrum readout uses N trajectories sampled from the replay buffer. Coverage and the trajectory
  plots come from a separate deterministic evaluation rollout of 48 skills.
- **Pixels.** Every network (φ, policy, both critics) has its own copy of METRA's CNN. The replay buffer stores
  single frames and rebuilds the 3-frame stacks when sampling.
- **DMC** (`ssd/dmc.py`, `ssd/custom_dmc_tasks/`): METRA's coloured-floor tasks on current `dm_control`. The only
  change to METRA's task code is `np.in1d` → `np.isin` for NumPy 2.
- **Kitchen** (`ssd/kitchen/`): the D4RL / RAPS end-effector kitchen and LEXA wrapper that METRA uses, vendored
  with compatibility fixes for current MuJoCo, Gymnasium and NumPy.
- `SSDConfig` has further options (e.g. a decorrelation warm-up, an EMA target encoder for the reward or the
  readout) that the benchmark leaves at their defaults.
